## 2. Goals and prerequisites

Goal: *I can add multi-digit numbers by decomposing an addend, with partial sums, and with the addition algorithm, and I can pick a strategy that works well.*

- Decompose one addend by place value and add the parts one at a time.
- Find partial sums by place (thousands, hundreds, tens, ones) and add them.
- Use the standard algorithm: line up by place, start at the ones, regroup 10 of a place as 1 of the next place, including into a new ten-thousands place.
- Add numbers with different numbers of digits (3 + 4 digits, 5 + 4 digits).
- Judge someone else's strategy; decide which information in a problem is needed; read "fewer than" problems correctly; solve two-step and "how many packs" problems.

Prerequisites: 2-1 (place value), 2-6 (partial sums), 2-7 (decompose), 2-10 (fluently add within 1,000).

## 3. Vocabulary

- **Addend** — a number you add. In 2,000 + 500, both are addends.
- **Sum** — the answer to an addition problem.
- **Decompose** — break a number into parts. 1,569 = 1,000 + 500 + 60 + 9.
- **Partial sums** — the sums you get when you add one place at a time; add them to get the total.
- **Algorithm** — a set of steps you do the same way every time.
- **Regroup** — trade 10 of one place for 1 of the next place (10 ones → 1 ten).
- **Strategy** — a way to solve a problem.

## 4. Methods taught in Learn

1. **Decompose an addend.** Keep the first addend; break the second into thousands, hundreds, tens, ones; add each part, keeping a running total. Book example: 2,322 + 1,000 = 3,322; + 500 = 3,822; + 60 = 3,882; + 9 = 3,891. Reasoning: adding the parts is the same as adding the whole number.
2. **Partial sums.** Add each place separately and write each partial sum with its full value (2,000 + 1,000 = 3,000; 300 + 500 = 800; 20 + 60 = 80; 2 + 9 = 11), then add them: 3,891.
3. **Addition algorithm.** Line up by place. Start at the ones. If a place adds to 10 or more, write the ones digit of that sum and regroup 1 to the next place (write a small 1 above it). Book example: 2 + 9 = 11 → write 1, regroup 1 ten.
4. **Choose a strategy / useful information.** Any strategy works; choose the one that is efficient for the numbers. Extra numbers in a word problem may not be needed (book: the 1,350 starting amount).

## 5. Guided sequence (Learn steps)

Five steps. Learn demo numbers (not reused in Your Turn): 3,146 + 2,537; 2,457 + 1,368; 6,184 + 359; 5,736 + 4,582; 2,180 + 3,465; 4,250 + 1,375.

### Step 1 · Decompose an addend
Example slides:
1. "A school library has 3,146 books. It gets 2,537 more. How many books now? 3,146 + 2,537."
2. "Break 2,537 into thousands, hundreds, tens and ones: 2,000 + 500 + 30 + 7." (show the four parts in colour)
3. Chain, one line at a time: 3,146 + 2,000 = **5,146** · 5,146 + 500 = **5,646** · 5,646 + 30 = **5,676** · 5,676 + 7 = **5,683**.
4. "3,146 + 2,537 = **5,683**."

Your Turn (`parts`): generate a (4-digit), b (4-digit, all digits non-zero), a + b ≤ 9,999. Prompt "{a} + {b}. Add one part of {b} at a time." Four `num` parts labeled "{a} + {b_th} =", "… + {b_h} =", "… + {b_t} =", "… + {b_o} =" (each label shows the previous running total once it is known, or the parts are labeled with the expected previous total — the builder can show running totals computed from the correct answers so one slip doesn't cascade). The last part is the sum. Hint: "Add the thousands first. Only the thousands digit changes."

### Step 2 · Partial sums
Example slides (vertical layout, static `vcalc` render with partial-sum rows — §13 A, "partials" display):
1. "2,457 + 1,368. Add each place. Write what each part is worth."
2. Thousands: 2,000 + 1,000 = **3,000**.
3. Hundreds: 400 + 300 = **700**.
4. Tens: 50 + 60 = **110**.
5. Ones: 7 + 8 = **15**.
6. "Add the partial sums: 3,000 + 700 + 110 + 15 = **3,825**."

Your Turn (`parts`): generate two 4-digit addends with at least one place summing to 10+ and total ≤ 9,999. Five `num` parts: Thousands, Hundreds, Tens, Ones (each as a full value, e.g. 110 not 11), Total. Hint: "Write the value: 5 tens + 6 tens = 11 tens = 110."

### Step 3 · The addition algorithm
Example slides (vertical algorithm with regroup marks — §13 A):
1. "Same problem, fewer steps: 2,457 + 1,368. Line up the places. Start with the ones."
2. Ones: 7 + 8 = 15. "15 ones = 1 ten and 5 ones. Write **5**. Regroup the 1 ten — write a small 1 above the tens."
3. Tens: 1 + 5 + 6 = 12. "12 tens = 1 hundred and 2 tens. Write **2**. Regroup 1 above the hundreds."
4. Hundreds: 1 + 4 + 3 = **8**. Thousands: 2 + 1 = **3**.
5. "2,457 + 1,368 = **3,825** — the same answer as partial sums. The algorithm just writes less."

Your Turn (`vcalc`, op +): two 4-digit addends, sum ≤ 9,999, with 1–2 regroupings (never in every place). The child fills the answer row right to left; carry boxes are available but not graded. Hint: "Start with the ones. If a place makes 10 or more, write the ones digit and regroup 1."

### Step 4 · Line up different sizes and go past 9,999
Example slides:
1. "6,184 + 359: line up the **ones** under the ones. 359 has no thousands." (vcalc shows an empty thousands cell for 359)
2. Work it: 4 + 9 = 13 → 3, regroup; 1 + 8 + 5 = 14 → 4, regroup; 1 + 1 + 3 = 5; 6 → **6,543**.
3. "5,736 + 4,582: Ones 6 + 2 = 8. Tens 3 + 8 = 11 → 1, regroup. Hundreds 1 + 7 + 5 = 13 → 3, regroup. Thousands 1 + 5 + 4 = 10 → write 0, regroup 1 **ten thousand**."
4. "The sum is **10,318** — a 5-digit number. Partial sums agree: 9,000 + 1,200 + 110 + 8 = 10,318."

Your Turn (`vcalc`, op +): random choice of (a) 4-digit + 3-digit, (b) 4-digit + 4-digit with sum 10,000–18,000, (c) 5-digit (10,000–29,999) + 4-digit, sum ≤ 39,999. Answer row has one more box than the longest addend. Hint: "Line up the ones. Keep going left until every place is added — including a regrouped 1."

### Step 5 · Choose a strategy and solve problems
Example slides:
1. "Useful information: A zoo had 2,180 visitors on Friday and 3,465 on Saturday. On Friday, 450 visitors bought hats. How many visitors came on both days?" "We need 2,180 and 3,465. The 450 hat buyers are already counted on Friday — we don't need that number." 2,180 + 3,465 = **5,645**.
2. "Fewer than: Ben scored 1,375 fewer points than Ava. Ben scored 4,250. Ava scored *more*, so add: 4,250 + 1,375 = **5,625**." Bar picture: Ava's bar = Ben's bar + 1,375.
3. "Which strategy? 3,000 + 2,999 → decompose or adjust. 4,786 + 3,659 → the algorithm. Any strategy that keeps the places straight is fine."

Your Turn (`parts`): generated word problem from two templates — (a) total with one extra number, (b) "fewer than" find the larger. Part 1 `multi`/`choice`: "Which numbers do you add?" (for (a): select the two needed numbers; for (b): choice of "{small} + {diff}" ✓ / "{small} − {diff}" / "{diff} − {small}"). Part 2 `num`: the answer. Hint: "Which numbers answer the question? If someone has fewer, the other person has more."

Learn reflection: "How do you decide which addition strategy to use?" Idea: "Look at the numbers. If one number is easy to break apart or close to a ten or hundred, use mental math. For big numbers with lots of regrouping, the algorithm is quick."

## 10. Common mistakes and coaching

- Forgetting the regrouped 1 (548 + 376 → 814). Fix: write the small 1 above the next place every time.
- Writing the whole place sum (7 + 8 = 15, writing "15" in the ones). Fix: one digit per box; the ten moves left.
- Lining up the left digits instead of the ones (8,365 + 247). Fix: start lining up from the right.
- Stopping before the last regroup (5,736 + 4,582 → 0,318). Fix: if there is a regrouped 1 left, it goes in a new place.
- Decomposing wrongly (72 + 300 + 3 for 365). Fix: add the parts back up to check they make the addend.
- Subtracting in "fewer than" problems. Fix: decide who has more; draw two bars.
- Using every number in a word problem. Fix: re-read the question; cross out what is not needed.
- Packs: answering 2 because 650 ÷ 240 "is about 2". Fix: the packs must cover the whole amount.

## 11. Parent Guide content

- **Goal**: add numbers up to 5 digits three ways and choose a good way.
- **Words**: addend, sum, decompose, partial sums, algorithm, regroup, strategy.
- **Demonstrate**: (1) 3,146 + 2,537 by adding 2,000, 500, 30, 7. (2) 2,457 + 1,368 by partial sums (3,000; 700; 110; 15). (3) Same problem with the algorithm, saying "15 ones is 1 ten and 5 ones." (4) 5,736 + 4,582 = 10,318 — the last regroup makes a new place.
- **Ask**: "What place do you start with?" "What did you do with the extra ten?" "Do the parts add back up to the number?" "Which numbers does the question need?" "Who has more?"
- **Mistakes**: as §10.
- **Checklist**: decomposes an addend and keeps a running total · finds partial sums with full values · uses the algorithm with regrouping, including into a new place · lines up numbers of different sizes · judges another person's strategy · solves "fewer than", extra-information, packs, and two-step problems.

## 13. New interaction or model needed

**A. `vcalc` — vertical addition/subtraction algorithm** (shared with 2-15, Unit Review, and earlier lessons 2-10/2-11 if they want it).

Data: `{ type: 'vcalc', op: '+' | '-', top: 2457, bottom: 1368, answer: 3825, blanks?: {...}, carries?: true }`.

Layout: a grid of digit columns right-aligned by place (ones at the far right), with small place headers (TTh, Th, H, T, O — only as many as needed). Commas are drawn as thin non-input separators between thousands and hundreds. Row 1: `top` digits. Row 2: the operator at the far left, then `bottom` digits (missing high places are blank, never 0). A rule. Row 3: one input box per column — number of boxes = digits of the longer number, +1 for addition (so a regroup into a new place has a home). Above row 1 (addition only): one small optional "regroup" box per column except the ones, for the child's carry marks; **not graded**, saved with the answer.

Input: one digit per box (numeric keypad on mobile), focus starts at the ones box and moves **left** after each digit; Backspace moves right. Arrow keys move freely.

Grading: read the answer row as a number (leading empty boxes are fine; a leading 0 is accepted only as an empty-equivalent). Correct if it equals `answer`. Feedback/explanation is generated column by column: "Ones: 7 + 8 = 15. Write 5, regroup 1 ten." etc.

Static render `vcalcHTML({ top, bottom, op, carries: [..] , result: 'none' | 'all' | k (show the k rightmost result digits), partials: [3000, 700, 110, 15], focus: placeIndex })` for Learn slides: shows carry digits in an accent colour, highlights the focus column, and (for partial sums) lists the partial-sum rows under the rule with a second rule and the total.

**B. Bar picture (static, optional)** for "fewer than" (Learn 5): two horizontal bars, the longer one split into "same as Ben" + "1,375 more". If another lesson (2-9) adds a bar-diagram helper, reuse it.
