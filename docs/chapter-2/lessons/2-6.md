## 2. Goals and prerequisites

Goals
1. Decompose a 3-digit number by place value (hundreds + tens + ones).
2. Add matching places to get partial sums; add the partial sums for the total.
3. Record it two ways: in a row (equations) and stacked (vertical), and know the total is the same either way.
4. Work backward: from partial sums, name the two original addends.
5. Find and explain partial-sum mistakes (stopping at one partial sum; writing a partial sum in the wrong place).
6. Solve word problems, including doubling and three addends.

Prerequisites: place value and expanded form (2-1), adding multiples of 10 and 100, basic facts.

## 3. Vocabulary

- **Decompose** — break a number apart into smaller parts. 368 = 300 + 60 + 8.
- **Place value** — what a digit is worth because of its place (hundreds, tens, ones).
- **Partial sum** — the sum of one place: the hundreds, the tens, or the ones.
- **Addend** — a number you add.
- **Sum** — the total when you add all the partial sums.
- **Stack** — write numbers one under the other, lining up the places.

## 4. Methods taught in Learn

1. **Decompose each addend by place value** (place-value chart). 367 → 300, 60, 7; 145 → 100, 40, 5.
2. **Partial sums in a row (One Way):** hundreds + hundreds, tens + tens, ones + ones, each as an equation; then add the three partial sums. Book: 400 + 100 + 12 = 512.
3. **Stacked partial sums (Another Way):** stack the addends, write each partial sum below the line (labelled 300 + 100, 60 + 40, 7 + 5), draw a line, add down. Same 512.
4. **Why the same?** Same parts, same total — only the layout changes (Be Curious icons, Math is… Explaining).
5. **Partial sums must all be added** (Work Together): 500 is one partial sum, not the answer; 309 + 225 = 534.
6. **Work backward** (5–6): each partial-sum equation shows one place of each addend; the first numbers build one addend, the second numbers build the other.
7. **Three addends** (12): add three hundreds, three tens, three ones.

## 5. Guided sequence (Learn steps)

Five steps. Demo numbers (Your Turn avoids these exact pairs): 368 + 154, 406 + 237, 345 + 123, 132 + 305 + 214, 163 + 163, and the book pairs 367 + 145, 309 + 225, 216 + 382.

Your Turn generator (shared, "PS pair"): a, b random 3-digit (101–899), a + b ≤ 999, no digit of a or b is 0 in more than one place, ones sum ≥ 10 **or** tens sum ≥ 10 (at least one partial sum needs regrouping in the final add), (a, b) not a demo pair.

### Step 1 — Break apart by place value
Example parts:
1. Place-value chart (existing `chart`-style display) with 368 over 154.
2. "368 = **300 + 60 + 8**." (colour each place as in the shared place colours)
3. "154 = **100 + 50 + 4**."
Your Turn: `parts`, three `num` parts — "Decompose n: ___ + ___ + ___" with labels "hundreds", "tens", "ones"; n random 3-digit with non-zero tens and ones. Answers: hundreds value, tens value, ones value (e.g. 400, 70, 2 — not digits). Hint: "What is each digit worth?" (Alternatively reuse the existing `expanded` question type if its UI fits.)

### Step 2 — Partial sums in a row
Example parts:
1. "368 + 154. Add the hundreds: **300 + 100 = 400**."
2. "Add the tens: **60 + 50 = 110**."
3. "Add the ones: **8 + 4 = 12**."
4. "Add the partial sums: **400 + 110 + 12 = 522**."
Your Turn: model M-STACK in **row mode** (§13) for a PS pair: the child fills each place pair and its partial sum, then the total. Grading: every field (6 place values, 3 partial sums, total). Hint: "Hundreds with hundreds, tens with tens, ones with ones." (Fallback with existing `parts`: three `num` parts labelled "Hundreds: 300 + 100 =", "Tens: …", "Ones: …" plus "Sum:"; place values pre-filled.)

### Step 3 — Stack the partial sums
Example parts:
1. Stacked: 368 over + 154, line.
2. Partial sums appear one by one: 400 (300 + 100), 110 (60 + 50), 12 (8 + 4), each with its left label.
3. Line, total **522**. "Same answer as the row! Same parts, just written a different way." (Show the Be Curious idea: the same 11 icons in rows of 5 or rows of 3 — 11 either way.)
Your Turn: M-STACK in **stacked mode**, new PS pair: inputs for the three partial sums and the total (labels shown). Then `choice` "Why is the sum the same in a row or stacked?" → "We add the same partial sums. Only the way we write them changes." (distractors: "Stacking makes the sum bigger." / "It isn't always the same." ). Hint: "Line up the places."

### Step 4 — Every partial sum counts (and working backward)
Example parts:
1. Work Together idea with new numbers: "Rami adds **406 + 237**. His partial sums are 600, 30, 13. Rami says the sum is 600." Stacked display. "600 is only the hundreds! Add all three: 600 + 30 + 13 = **643**."
2. "Working backward: 300 + 100 = 400, 40 + 20 = 60, 5 + 3 = 8. The first numbers make **345**. The second numbers make **123**. So the equation was 345 + 123 = 468." (book idea, Whitney, with new numbers)
Your Turn: `parts`: shows three row equations from a generated pair (a, b): "h₁ + h₂ = …, t₁ + t₂ = …, o₁ + o₂ = …". Parts: `num` "First addend" → a; `num` "Second addend" → b; `num` "Sum" → a + b. **Accept the two addends in either order** (if first = b and second = a, both are marked right — needs a tiny `either` flag, §13). Hint: "Use the first number in each line to build one addend."

### Step 5 — Three addends and story problems
Example parts:
1. "**132 + 305 + 214**. Hundreds: 100 + 300 + 200 = 600. Tens: 30 + 0 + 10 = 40. Ones: 2 + 5 + 4 = 11. 600 + 40 + 11 = **651**." (stacked, three addends)
2. "Story: A farm stand sold 163 pumpkins on Saturday and the same number on Sunday. 163 + 163: 200 + 120 + 6 = **326** pumpkins."
Your Turn: word problem, `parts`: M-STACK stacked mode for a generated PS pair inside a short context drawn from a list (stickers, steps, books, shells) + `num` total with unit. Hint: "Which two numbers do you add?"

Learn reflection: "Why does place value matter when you use partial sums?" Idea: "You must add hundreds to hundreds and tens to tens. If you mix places, the partial sums are wrong."

## 10. Common mistakes and coaching

- Stopping after the hundreds partial sum (Jun, Amal). → "How many partial sums? Add them all."
- Writing digits instead of values (3 + 1 = 4 instead of 300 + 100 = 400). → "What is the 3 worth?"
- Dropping the ten in a partial sum (7 + 5 → "2"). → The ones partial sum is 12; write the whole 12.
- Lining up places wrong when stacking. → Use the place-value colours / grid.
- In reverse problems, mixing first and second numbers across lines. → First numbers build one addend.

## 11. Parent Guide content

- **Goal:** Add 3-digit numbers by breaking them apart by place value and adding the partial sums.
- **Words:** decompose, place value, partial sum, addend, sum, stack.
- **Demonstrate:** Write 367 + 145. Say each number in expanded form. Add hundreds (400), tens (100), ones (12). Add 400 + 100 + 12 = 512. Then write it stacked and show the same three partial sums give the same 512. Show "500 isn't the answer" with 309 + 225.
- **Ask:** "What is this digit worth?" · "Did you add every partial sum?" · "Which numbers made this partial sum?" · "Would the answer change if you stacked it?"
- **Checklist:** decomposes by place value · row partial sums · stacked partial sums · says why both give the same sum · finds addends from partial sums · finds "only the hundreds" and "dropped ten" mistakes · three addends · word problems.

## 13. New interaction or model needed

**M-STACK — partial-sums model (new question type `pstack`, shared with later add lessons 2-10/2-14):**
- Config: `addends: [a, b]` or `[a, b, c]`; `mode: 'row' | 'stacked'`; `given`: which fields are pre-filled (e.g. place values shown in stacked mode, blank in row mode).
- **Row mode:** three lines `[h₁] + [h₂] = [H]`, `[t₁] + [t₂] = [T]`, `[o₁] + [o₂] = [O]`, then `[H] + [T] + [O] = [S]` (the last line's first three boxes echo the partial sums automatically; the child types S). With 3 addends each line has three place boxes.
- **Stacked mode:** addends right-aligned with "+" and a line; below, three rows: left label "300 + 100" (shown or typed), right box for the partial sum, a "+" before the last, line, total box.
- Grading: each place-value box = that addend's place value (300 not 3); partial sums = place totals; S = a + b (+ c). Feedback names the first wrong row. `correctText` shows the full worked model.
- Visual only (no inputs) variant for Learn slides and for "here is the work" prompts (O8, O9, PT3, T10).

**Small engine addition — `either` group for `num` parts:** two `num` parts marked `either: 'addends'` are correct if `{r1, r2} = {a, b}` as a set (used by reverse items). Without it, the builder can use a single `choice` of ordered pairs instead.
